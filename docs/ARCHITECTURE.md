# MidnightSun - architecture and developer notes

Technical notes for contributors (English). The Turkish user guide is the [README](../README.md).

## Project

Game streaming pipeline: DXGI Desktop Duplication screen capture feeding a zero-copy NVENC H.264 encoder, with a custom UDP transport ("GSMR" protocol) between host and client. Windows-only, DirectX 11.

**One executable** (`MidnightSun.exe`, GUI subsystem, entry `WinMain` in `app_main.cpp`): the launcher home screen picks the role per session — "Bu bilgisayarı yayınla" runs `RunHostSession()` (HostSession.cpp), picking/typing a target runs `RunClientSession()` (ClientSession.cpp) — and the app returns to the launcher after every session. One config file: `midnightsun_config.json` (AppConfig.h; `"show_console": 1` attaches a log console), **fully editable in-app** via the launcher's settings page (gear icon) — users never open the JSON by hand.

## Build

Requires MSVC 2022 with the "Desktop development with C++" workload, Windows SDK 10.0, and an NVIDIA driver new enough for NVENC SDK 12.0, i.e. ≥ 522.25 (the version of `extern/nvenc/nvEncodeAPI.h` currently in the repo — chosen so any RTX 4070-capable driver works; the original SDK 13.1 header is kept at `extern/nvenc/sdk13/nvEncodeAPI.h`, swap it back for SDK 13 features). `NvencEncoder.cpp` handles both via compile-time guards.

**All sources are UTF-8 without BOM and MUST be compiled with `/utf-8`** — without it MSVC decodes the Turkish wide literals (L"Yayınla"…) with the system codepage and the UI text renders garbled. CMake adds the flag; add it to manual `cl` lines too.

Compile each module from a Developer Command Prompt (or after `VsDevCmd.bat`), appending `/utf-8` to each line:

```
cl /std:c++20 /EHsc /W4 /permissive- /I. /c ScreenCapture.cpp
cl /std:c++20 /EHsc /W4 /permissive- /I. /c NvencEncoder.cpp
cl /std:c++20 /EHsc /W4 /permissive- /I. /c StreamSender.cpp
cl /std:c++20 /EHsc /W4 /permissive- /I. /c StreamReceiver.cpp
cl /std:c++20 /EHsc /W4 /permissive- /I. /c InputCapture.cpp
cl /std:c++20 /EHsc /W4 /permissive- /I. /c InputInjector.cpp
cl /std:c++20 /EHsc /W4 /permissive- /I. /c AudioCapture.cpp
cl /std:c++20 /EHsc /W4 /permissive- /I. /c AudioPlayer.cpp
cl /std:c++20 /EHsc /W4 /permissive- /I. /c Crypto.cpp
cl /std:c++20 /EHsc /W4 /permissive- /I. /c Discovery.cpp
cl /std:c++20 /EHsc /W4 /permissive- /I. /c LauncherWindow.cpp
cl /std:c++20 /EHsc /W4 /permissive- /I. /c StatusWindow.cpp
cl /std:c++20 /EHsc /W4 /permissive- /I. /c AppConfig.cpp
cl /std:c++20 /EHsc /W4 /permissive- /I. /c HostSession.cpp
cl /std:c++20 /EHsc /W4 /permissive- /I. /c ClientSession.cpp
```

Link deps are declared via `#pragma comment` in the .cpp files (`d3d11.lib`, `dxgi.lib`, `d2d1.lib`, `dwrite.lib`, `dwmapi.lib`, `ws2_32.lib`, `bcrypt.lib`, `xinput.lib`, `winmm.lib`, `setupapi.lib`, `ole32.lib`, `oleaut32.lib`, `avrt.lib`). `nvEncodeAPI64.dll` is loaded at runtime — no import library needed.

**Preferred build: `build_all.bat`** (repo root, needs CMake + VS 2022). It builds the two vendored SDK sources under `extern/` (Opus 1.5.2 → `extern/opus/lib/x64/opus.lib`, ViGEmClient → `extern/vigemclient/lib/x64/ViGEmClient.lib`; both skipped once the .lib exists), then configures and builds the project via `CMakeLists.txt` into `build\Release\MidnightSun.exe` (single WIN32 target; `midnightsun_config.json` copied next to the exe). `build_all.bat clean` wipes all build trees and the produced .libs. Opus's CMake reads its version from `extern/opus/package_version` (the source is a git checkout with `.git` stripped — keep that file).

**Resources & packaging:** `MidnightSun.rc` (app icon `app.ico` = `IDI_APPICON` in `resource.h` + VERSIONINFO) and `MidnightSun.manifest` (PerMonitorV2 DPI awareness) are target sources; CMake merges `.manifest` sources into the linker manifest via mt.exe — do NOT add an RT_MANIFEST to the .rc, it would collide. `installer.iss` (Inno Setup 6, `ISCC.exe installer.iss`) packages `dist\MidnightSun\` (made by `tools\package.ps1`: exe + app-local VC++ runtime DLLs + default config + licence files) into `Output\MidnightSun-Kurulum.exe`: shortcuts, program-scoped inbound-UDP firewall rule via netsh (deleted on uninstall), config preserved on update (`onlyifdoesntexist`) and made user-writable (`Permissions: users-modify`), shortcuts start in `{app}` because the config path is relative to the working directory. `README.md` = Turkish user guide, `TANITIM.md` = marketing copy.

## Architecture

| File | Role |
|---|---|
| `app_main.cpp` | `WinMain`: config + COM + the launcher→session→launcher loop; persists config when the launcher reports `configChanged`, upserts the connect target into `saved_devices` (migrates the legacy single `server_ip` on first run) |
| `AppConfig.h/.cpp` | `midnightsun_config.json` load/save (both roles' keys in one file) + `saved_devices` array (named targets, `kMaxSavedDevices` 6, `UpsertSavedDevice`/`RemoveSavedDevice`), `require_approval`, JSON string escaping |
| `HostSession.h/.cpp` | One hosting session as a callable (former server main): capture→encode→send pipeline + discovery responder + status window; returns when the status window closes |
| `ClientSession.h/.cpp` | One viewing session as a callable (former client main): receive→decode→render + input capture; returns on Shift+ESC |
| `ScreenCapture.h/.cpp` | DXGI capture, D3D11 device owner, triple-buffer ring |
| `NvencEncoder.h/.cpp` | NVENC H.264 encoder, consumes textures from the ring |
| `VideoScaler.h/.cpp` | Server GPU downscale (D3D11 video processor BGRA blit) between capture and NVENC; `encode_height` in server_config.json, 0 = native, passthrough when source ≤ target |
| `NetworkProtocol.h` | GSMR wire format: 18-byte packet header, fragmentation rules, keepalive control kinds (`KeepaliveKind`: ping/pong/keyframe-request/receiver-report), `EncodedFrame`/`StreamStats`/`ReassemblySlot`, endian-safe serialize/deserialize |
| `Crypto.h/.cpp` | Optional AES-256-GCM datagram encryption+auth via Windows CNG (bcrypt.lib); `"psk"` in both configs, per-direction keys = SHA-256(psk+":c2s"/":s2c"), wire = header(AAD) + 12B nonce + ciphertext + 16B tag; empty PSK = pass-through |
| `StreamSender.h/.cpp` | Server transport: lock-free 64-slot outbound ring, fragmentation, client discovery (post-auth when PSK set), keepalive/RTT, `onKeyframeRequest`/`onReceiverReport` callbacks; connect approval (`setRequireApproval` → new endpoints wait in "pending", `onClientRequest` fires once, `resolvePending(allow)` adopts or session-blocks by IP) |
| `StreamReceiver.h/.cpp` | Client transport: reassembly (80 ms eviction), 8-seq reorder window, 4-slot jitter buffer, disconnect/reconnect, auto keyframe requests on loss (250 ms throttle), 1 Hz receiver report |
| `InputPacket.h` | INPUT wire format v2: fixed 55-byte LE snapshot — 256-bit key bitmask (bit = raw VK code, L/R modifiers distinct), relative-delta OR absolute 0..65535 mouse (flags bit0), 5 mouse buttons (incl. X1/X2), wheel deltas |
| `InputCapture.h/.cpp` | Client input capture: Raw Input keyboard/mouse + XInput pad 0, 120 Hz send via `StreamReceiver::sendInput()`; wheel arrives from RenderWindow messages (`addWheel`), absolute pointer via `setAbsolutePointer`/`setAbsoluteMouse` |
| `InputInjector.h/.cpp` | Server input injection: `SendInput` (scancode, 256-key diff; `MOUSEEVENTF_ABSOLUTE` in desktop mode, relative in game mode) + ViGEm virtual Xbox 360 pad |
| `AudioCapture.h/.cpp` | Server audio: WASAPI loopback → format adapt → Opus 20 ms frames → `sendAudio()` |
| `AudioPlayer.h/.cpp` | Client audio: Opus decode + PLC → 8-slot jitter ring → WASAPI shared render, drift correction |
| `Discovery.h/.cpp` | IP-free pairing: LAN auto-discovery (GSDS/GSDR broadcast on fixed UDP `kDiscoveryPort` 47800; responder answers with hostname+stream port+PSK flag) and the pairing code (Crockford base32 "XXXX-XXXX-XXXX" = IPv4+port+CRC-8); `GetLocalIpv4()` via connected-UDP trick |
| `LauncherWindow.h/.cpp` | Home screen (shown before each session): borderless dark D2D window, per-monitor DPI; device list = named `saved_devices` (× to forget, live/offline dot) + LAN-discovered servers; code/IP entry (Ctrl+V paste, Crockford typo tolerance); settings page behind the gear icon (bitrate / encode height / fps cyclers, port, PSK, approval toggle — writes the config draft on Kaydet, `LaunchChoice::configChanged` tells the caller to save); modal `run(AppConfig&)` returns the choice |
| `StatusWindow.h/.cpp` | Server status window on its own UI thread, per-monitor DPI: state pill, big click-to-copy pairing code, address + stats lines; "—" minimizes to the system tray (restore / copy code / stop menu); `requestApproval()` shows the in-window "İzin ver / Reddet" prompt, host loop polls `takeApprovalDecision()`; closing it = server shutdown |
| `resource.h` / `MidnightSun.rc` / `app.ico` / `MidnightSun.manifest` | App icon (`IDI_APPICON`, also the window-class + tray icon), VERSIONINFO, PerMonitorV2 DPI manifest |
| `installer.iss` | Inno Setup 6 script (shortcuts + firewall rule; see Build) |
| `extern/nvenc/nvEncodeAPI.h` | NVIDIA Video Codec SDK 13.1 (runtime DLL load, no link dep) |

**Data flow:** `ScreenCapture` owns the `ID3D11Device`. `NvencEncoder::initialize()` takes that same device pointer. `getLatestFrame()` returns a borrowed `ID3D11Texture2D*`; pass it directly to `encode()` — NVENC reads it zero-copy from VRAM via `NvEncRegisterResource`/`NvEncMapInputResource`. The encoded Annex B bytes are wrapped in an `EncodedFrame` (defined in `NetworkProtocol.h`, not `NvencEncoder.h`) and handed to `StreamSender::sendFrame()`; on the client, `StreamReceiver` reassembles and fires `onVideoFrame` in order.

**GSMR transport (NetworkProtocol.h):** UDP, max 1400-byte datagrams (18-byte header + ≤1354 payload — `kCryptoOverhead` 28 bytes reserved unconditionally so fragment layout matches in both crypto modes), little-endian fields. Sequence numbers advance per logical *unit* (frame), not per packet; fragments share the sequence and differ by `fragmentId`. Keepalive `fragmentId` selects a control message (`KeepaliveKind`): 0 ping / 1 pong (timestamp echoed, RTT computed by the original sender), 2 keyframe request (client→server), 3 receiver report (client→server, 8 B: u32 VIDEO frames expected + u32 completed over the last ~1 s; audio sequences deliberately excluded from "expected" — `checkSequenceWindow(countExpected)`). Discovery: the server streams to whoever sent the last valid datagram (the receiver pings in `start()` for exactly this reason); with a PSK, only GCM-authenticated datagrams count — that closes the session-hijack hole. With `require_approval` (default ON) a new endpoint instead parks in "pending" — no packets processed, no pong — until the host answers the status-window prompt; approved IPs are trusted and denied IPs ignored for the rest of the session (the client's 120 ms input heartbeat means adoption happens within ~1 heartbeat of approval). No handshake, no retransmission. Loss recovery: the receiver itself requests keyframes (reassembly eviction, gap delivery, decoder-not-primed on join/reconnect; 250 ms throttle) → `onKeyframeRequest` → `NvencEncoder::requestKeyframe()`; there is **no periodic IDR anymore** — intra refresh heals silent corruption. The receiver report feeds the adaptive bitrate controller in `server_main`'s encode loop: >2% frame loss → bitrate × 0.7 (2 s cooldown), 5 clean reports → × 1.15, bounded [max(2 Mbps, max/8), config max], applied via `NvencEncoder::setBitrate()` (in-place `NvEncReconfigureEncoder`, no IDR, no reset).

**Pairing & UI (no more typing IPs, no more editing JSON):** the app's home screen is `LauncherWindow` — a modal dark window whose `run(AppConfig&)` returns a `LaunchChoice`: **Host** (the "Bu bilgisayarı yayınla" card), **Connect** (a click on the device list — named `saved_devices` rows first (live/offline dot, hover × forgets), then LAN-discovered servers from a background `DiscoverServers()` thread ~every 1.6 s — or a pairing code / manual `ip[:port]` typed into the input line), or **Cancel** (close/Esc = quit). A Connect choice is upserted into `saved_devices` (name = discovery hostname when known) and mirrored to `server_ip`/`server_port` by `app_main`. The gear icon opens the **settings page** (same window): max bitrate, encode height + FPS cyclers, port, PSK, and the connect-approval toggle; Kaydet validates, writes the draft into the config and flags `configChanged` (Esc/Vazgeç discards). Both launcher and status windows scale per-monitor (PerMonitorV2 manifest + `WM_DPICHANGED`; layout constants are DIPs, the D2D target gets `SetDpi`, mouse coords divide by the scale). Hosting starts a `DiscoveryResponder` (UDP 47800, fixed constant shared by both ends — firewall must allow it; the installer adds a program-scoped rule) and a `StatusWindow` showing the pairing code = `EncodePairingCode(GetLocalIpv4(), stream port)`; the "—" button minimizes it to the tray (restore / copy code / stop), an incoming connect request restores + flashes it with the approval prompt, and closing it ends the host session. The code encodes an *address*, so it works wherever that address is reachable (LAN/VPN/port-forward); there is no rendezvous server / NAT traversal. With a PSK configured, discovery replies advertise `pskRequired` (shown as a "PSK" tag in the launcher list) — the PSK itself is set on both machines via the settings page.

**Client presentation:** `RenderWindow` presents with `Present(0, DO_NOT_WAIT)`; when the OS/driver supports it the swap chain is created with `DXGI_SWAP_CHAIN_FLAG_ALLOW_TEARING` and presents add `DXGI_PRESENT_ALLOW_TEARING` (borderless-fullscreen latency ↓ up to one vsync; falls back silently when unsupported).

**Transport threading:** sender's `sendFrame()` (takes `EncodedFrame` by value; caller `std::move`s so the bitstream is never copied)/`sendAudio()` must come from one producer thread; a lock-free 64-slot ring (atomic-pointer slots; drop-oldest-on-full via exchange+CAS stealing, keyframes never dropped) feeds the `GSMR-Send` thread, which also polls inbound (WSAPoll 10 ms) for discovery/keepalive/input. Receiver callbacks all fire on the `GSMR-Recv` thread — keep them fast. Both sides run a 1 Hz stats thread behind `getStats()`.

**Audio path (server → client):** `AudioCapture` ("Audio-Capture" thread, owns its COM objects + Opus encoder) does WASAPI loopback on the default render endpoint, event-driven, adapting the mix format to 48 kHz stereo float32 (stateful linear resampler, standard downmix weights for >2 ch, int16 scaling). 960-sample (20 ms) Opus frames at 128 kbps using `OPUS_APPLICATION_RESTRICTED_LOWDELAY` (deliberate: the lowest-latency Opus mode, CELT-only — not VOIP/AUDIO). Timestamps are synthesized from the encoded-sample counter (exactly 20 ms apart), so the receiver's gap detector (>25 ms) fires only on real packet loss. WASAPI loopback emits nothing while the system is silent — the player just underruns to silence. On the client, `AudioPlayer::onPacket()` (GSMR-Recv thread) decodes under a mutex, conceals detected gaps with up to 4 PLC frames (`opus_decode_float(nullptr)`), and pushes into an 8-slot jitter ring (drop-oldest when full). The "Audio-Render" thread plays via WASAPI shared mode with `AUTOCONVERTPCM | SRC_DEFAULT_QUALITY` (engine converts from 48 kHz float stereo, no render-side resampler), primes at 2 frames (re-primes after a full drain), fills silence on underrun (PLC is for network loss only), and sheds one 20 ms frame when the IAudioClock-measured buffered-audio EMA exceeds the prime target by 5 ms (clock drift). Both threads are MMCSS "Pro Audio" boosted.

**Input path (client → server):** `InputCapture` accumulates Raw Input keyboard/mouse state (hidden message-only window, `RIDEV_INPUTSINK`, `Input-RawMsg` thread) into atomics; the `Input-Send` thread runs a unified 120 Hz timer (`timeBeginPeriod(1)`), polls XInput pad 0 (`dwPacketNumber` change detection, radial deadzones, 1 s reprobe backoff when disconnected), and ships a 55-byte `InputPacket` v2 via `StreamReceiver::sendInput()` whenever anything changed, plus a heartbeat every 120 ms. The key bitmask is 256 bits — **bit = raw VK code**, with generic shift/ctrl/alt resolved to `VK_LSHIFT`..`VK_RMENU` at capture (scancode for shift, `RI_KEY_E0` for ctrl/alt), so every keyboard key round-trips. **Wheel does NOT come from Raw Input**: Windows Precision Touchpad scrolling only exists as `WM_MOUSEWHEEL`/`WM_MOUSEHWHEEL` window messages, so `RenderWindow` forwards those into `InputCapture::addWheel()` (mice generate the same messages while the client window is foreground; handling both paths would double-scroll). Two mouse modes (F2 in the render window, default absolute): *absolute/desktop* — `RenderWindow` maps the local cursor through the letterbox rect to normalized 0..65535 (`onPointerAbs` → `setAbsolutePointer`), packet carries `InputFlags::kAbsoluteMouse`, injector uses `MOUSEEVENTF_ABSOLUTE` on the primary (captured) monitor, so every pointing device (touchpads included) maps 1:1 with client-side ballistics; *relative/game* — raw-input deltas, `MOUSEEVENTF_MOVE`, for FPS-style games. The client clips the (hidden) cursor to its window while foreground (`ClipCursor`, released on deactivate/shutdown). On the server, `StreamSender::onInputPacket` (GSMR-Send thread) feeds `InputInjector::inject()`, which diffs the 256-bit key state + 5 mouse buttons (incl. X1/X2 via `MOUSEEVENTF_XDOWN/XUP`) and injects only transitions, scancodes + `KEYEVENTF_EXTENDEDKEY` for the full E0 set (arrows, ins/del/home/end/pgup/pgdn, RCtrl/RAlt, Win keys, numpad-divide, ...). Both ends release-all on teardown: `InputCapture::stop()` sends a final neutral packet, `InputInjector::stop()` injects key-ups for everything still held. If the ViGEmBus driver is missing, the injector degrades to keyboard/mouse-only (logged; `start()` still returns true).

**ScreenCapture threading:**
- Control thread: `startCapture()` / `stopCapture()`. Device is created synchronously; duplication setup is deferred to the capture thread so transient failures retry with 250 ms backoff.
- Capture thread: owns the D3D11 immediate context; copies frames into the ring with `CopyResource`; `publishFrame` signals `m_frameCv`.
- Consumer thread: calls `waitForNewFrame(timeoutMs)` + `getLatestFrame()`. The host encode loop is frame-driven: it sleeps to the fps-cap deadline, then blocks on `waitForNewFrame` (≤1 frame interval) and encodes the instant a new capture lands — on timeout (static desktop) the previous frame is re-encoded, preserving the old fixed-tick behavior. `ID3D11Multithread` protection on the device makes this safe alongside the encoder's GPU submissions.

**Triple-buffer ring** (`m_slots[3]`): capture thread writes into `writeIndex`, swaps `write↔latest` under `m_frameMutex`. Consumer swaps `read↔latest` to pick up the newest frame. No per-frame allocation, no CPU readback, no frame-sized copies on swaps. `m_consumerHeldTexture` ComPtr pins the texture handed to the consumer across ring rebuilds caused by resolution changes.

**ScreenCapture resilience:** `ACCESS_LOST` → recreate duplication; `DEVICE_REMOVED`/`DEVICE_RESET` → recreate device + duplication. `WAIT_TIMEOUT` is silent (no new frame on a static desktop).

**NvencEncoder lifecycle:** `initialize(device, config)` loads `nvEncodeAPI64.dll`, checks the driver version ≥ SDK headers, opens the NVENC session. Frame dimensions are deferred to the first `encode()` call. A resolution change transparently tears down and rebuilds the session; the first output bitstream after the change is an IDR + SPS/PPS. `shutdown()` sends EOS, unregisters all textures, destroys the session, and frees the DLL.

**NVENC config:** preset P4 (P1 fallback) + `NV_ENC_TUNING_INFO_ULTRA_LOW_LATENCY`. Rate control is CBR with a single-frame VBV (`vbvBufferSize = bitrate / fps`) to bound worst-case send latency, plus spatial AQ (`enableAQ`, moves bits into flat areas where CBR "grain" shows first) and CABAC entropy coding. Infinite GOP with **intra refresh** (`enableIntraRefresh`, wave every ~4 s spanning ~fps/6 frames; auto-disabled with a log if the driver rejects it) instead of periodic IDRs — no more IDR quality pulse under the tight VBV. IDRs happen on the first frame, on resolution change, and on `requestKeyframe()`. `setBitrate()` (any thread) stores a pending target that `encode()` applies via `NvEncReconfigureEncoder` (no reset, no forced IDR); `m_initParams`/`m_encodeConfig` are kept as members for exactly this.

**Texture registration cache:** `registerOrLookup()` caches `NV_ENC_REGISTERED_PTR` by texture pointer and holds a `ComPtr` to keep the texture alive. The capture ring has exactly 3 textures, so the cache saturates after the first 3 frames and registration overhead disappears. Cache is flushed wholesale at `kMaxRegistrations = 8` to handle ring rebuilds at the same resolution.

**Audio device changes:** both `AudioCapture` and `AudioPlayer` register an `IMMNotificationClient` (stack-allocated, no-op refcount) for the default render endpoint. On `OnDefaultDeviceChanged` (eRender/eConsole) — or on any WASAPI call failing, e.g. `AUDCLNT_E_DEVICE_INVALIDATED` — the worker thread tears down its WASAPI objects and re-initializes on the new default, retrying every 500 ms while none exists. The Opus encoder/decoder, timestamp counter, and jitter ring survive the swap.

**Known gaps:**
- Cursor is composited on the CPU (small staging round-trip over the cursor rect in `ScreenCapture::compositeCursor`); pointer-only updates publish a frame so cursor motion is visible on a static desktop.
- Rotated monitors deliver unrotated frames (logged as a warning).
- Cross-device sharing (encoder on a separate GPU) requires `D3D11_RESOURCE_MISC_SHARED_NTHANDLE` + keyed mutex on the ring textures.
- Audio mix formats other than float32/int16 fail `AudioCapture::start()` (never seen in practice — the shared-mode mix format is float32).
- Crypto has no replay protection and no forward secrecy (static PSK-derived keys); the sequence window drops stale media, but a recorded input packet could in principle be replayed. Fine for LAN, not a TLS substitute.
- Server accepts only single-fragment (≤ `kMaxPayloadSize`) input packets (fine: `InputPacket` v2 is a fixed 55 bytes).
- Only XInput pad 0 is forwarded. F1/F2 are client-local hotkeys (overlay / mouse mode) and are filtered out of the key bitmask in `InputCapture::handleRawInput` — they never reach the server.
- Absolute mouse mode assumes the server captures the primary monitor (`MOUSEEVENTF_ABSOLUTE` maps to primary) — true for `ScreenCapture` today.
- Gamepad injection needs the ViGEmBus kernel driver installed on the server PC (https://github.com/nefarius/ViGEmBus/releases); without it the injector degrades to keyboard/mouse-only (logged, `start()` still succeeds).
- Pairing code carries IPv4+port only (no IPv6, no NAT traversal); LAN discovery is IPv4 broadcast on UDP 47800 and may be blocked by Windows Firewall profiles or AP client isolation.
- Approval state (trusted/blocked IPs) is per host session — restarting the host re-prompts everyone. With `require_approval` on and the status window unavailable (headless), pending clients can never be admitted (logged).
- While a client waits for approval it gets no feedback (the render window just stays black until admitted).
